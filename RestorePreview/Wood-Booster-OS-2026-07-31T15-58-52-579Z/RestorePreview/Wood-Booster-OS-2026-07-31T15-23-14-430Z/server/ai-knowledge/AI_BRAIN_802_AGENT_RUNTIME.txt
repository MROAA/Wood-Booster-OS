WOOD-BOOSTER AI PLATFORM
AGENT RUNTIME STANDARD

Version: 1.0
Status: Active
Priority: Critical

PURPOSE

This document defines the lifecycle and runtime behavior of every AI agent inside the Wood-Booster Intelligence Platform.

Each agent should start, work, pause, recover and stop in a predictable and traceable way.

--------------------------------------------------

MISSION

Provide a consistent runtime environment where specialized agents can execute tasks safely, efficiently and transparently.

--------------------------------------------------

--------------------------------------------------

STARTUP PROCESS

When an agent starts, it must:

1. Verify its Agent ID and version.
2. Load the Constitution and Core Values.
3. Load its role definition.
4. Load permissions.
5. Load relevant tools.
6. Load current project context when assigned.
7. Confirm readiness to the Orchestrator.

An agent must not accept work before startup validation succeeds.

--------------------------------------------------

TASK INTAKE

For every assigned task, the agent must receive:

- Task ID
- Objective
- Priority
- Deadline
- Required output
- Relevant project
- Related customer
- Dependencies
- Available evidence
- Acceptance criteria

If critical information is missing, the agent should request clarification or escalate.

--------------------------------------------------

CONTEXT LOADING

Load only context needed for the current task.

Preferred order:

1. Constitution
2. Role definition
3. Playbooks
4. Knowledge
5. Wisdom
6. Working Memory
7. Related project data
8. Tool state

Avoid loading unrelated information.

--------------------------------------------------

EXECUTION RULES

Every agent must:

- Follow permissions.
- Record important actions.
- Use approved tools.
- State uncertainty.
- Avoid duplicate work.
- Report blockers quickly.
- Preserve customer privacy.
- Follow the Agent Task Protocol.

--------------------------------------------------

WORK STATES

Ready

Available for work.

Working

Actively executing a task.

Waiting

Waiting for another task or dependency.

Blocked

Cannot continue without new information, permission or another agent.

Reviewing

Validating results before reporting.

Degraded

Operating with reduced capability.

Offline

Unavailable for tasks.

--------------------------------------------------

HEARTBEAT

Active agents should periodically report:

- Agent status
- Current task
- Progress
- Resource usage
- Last successful action
- Known blockers
- Health condition

The Orchestrator uses this heartbeat to detect unavailable or stalled agents.

--------------------------------------------------

RESOURCE MANAGEMENT

The runtime should monitor:

- CPU usage
- GPU usage
- Memory usage
- Context size
- Model availability
- Tool availability
- Request limits

Agents should release resources when tasks finish.

--------------------------------------------------

FAILURE HANDLING

When an agent fails:

1. Preserve task state.
2. Record the failure.
3. Retry when safe.
4. Use a fallback model or tool when allowed.
5. Reassign the task if necessary.
6. Escalate critical failures.
7. Create an audit record.

Never hide partial failure from the Orchestrator.

--------------------------------------------------

PAUSE AND RESUME

Before pausing, store:

- Current task state
- Completed steps
- Open questions
- Temporary assumptions
- Required next action

When resuming, validate that project data and permissions are still current.

--------------------------------------------------

COMPLETION PROCESS

Before completing a task, the agent must:

- Verify acceptance criteria.
- Validate the result.
- Record evidence.
- Report risks and uncertainty.
- Suggest the next action.
- Identify possible Knowledge, Wisdom or Playbook updates.
- Submit a standard agent report.

--------------------------------------------------

STOPPING AN AGENT

Before stopping, the agent must:

- Finish or safely hand over active work.
- Save required state.
- Release resources.
- Record final status.
- Notify the Orchestrator.

--------------------------------------------------

AGENT RETIREMENT

When an agent is retired:

- Disable new task assignment.
- Archive its role and performance history.
- Reassign active responsibilities.
- Preserve audit records.
- Update the Capability Registry.
- Remove unused permissions.

--------------------------------------------------

SUCCESS METRICS

The Agent Runtime succeeds when:

- Agents start reliably.
- Tasks are not lost.
- Blockers are visible.
- Failures recover safely.
- Resource use remains controlled.
- Results are traceable.
- Agent behavior remains consistent.

--------------------------------------------------

FINAL PRINCIPLE

An AI agent is not only a prompt.

It is a managed worker with a role, permissions, memory, tools, responsibilities and a complete lifecycle.
