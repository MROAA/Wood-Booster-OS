WOOD-BOOSTER AI AGENT PROTOCOL
CAPABILITY REGISTRY

Version: 1.0
Status: Foundational
Priority: Highest

PURPOSE

This document defines how the Wood-Booster Intelligence Platform describes the capabilities of every AI agent.

The registry enables the orchestration engine to select the best agent for every task.

--------------------------------------------------

MISSION

Maintain an accurate catalogue of what every agent can do, what it cannot do and when it should be selected.

--------------------------------------------------

AGENT REGISTRY ENTRY

Every registered agent must include:

Agent ID

Agent Name

Version

Status

Owner

Description

Primary Role

Supported Domains

Capabilities

Limitations

Required Tools

Accessible Knowledge Sources

Escalation Targets

Performance Metrics

Last Updated

--------------------------------------------------

CAPABILITY LEVELS

Level 1
Basic assistance

Level 2
Guided execution

Level 3
Independent execution

Level 4
Expert reasoning

Level 5
Strategic leadership

Capability levels should be evidence-based and reviewed regularly.

--------------------------------------------------

Automation

--------------------------------------------------

LIMITATIONS

Every agent must clearly state:

What it cannot do.

What requires another specialist.

What requires human approval.

Known weaknesses.

Confidence boundaries.

--------------------------------------------------

SELECTION RULES

The orchestration engine should prefer agents that:

Match the requested domain.

Have the required capability level.

Can access the necessary tools.

Have relevant project context.

Do not duplicate work already assigned.

--------------------------------------------------

REGISTRY MAINTENANCE

Review every agent periodically.

Retire obsolete agents.

Merge overlapping agents.

Create new specialists when recurring capability gaps are identified.

--------------------------------------------------

SUCCESS

The registry succeeds when:

The correct specialist is selected quickly.

Responsibilities are clear.

Duplicate capabilities decrease.

Agent collaboration improves.

--------------------------------------------------

FINAL PRINCIPLE

A great multi-agent system is built on clearly defined responsibilities.

Every agent should know its strengths, its limits and when another specialist should lead.
