AI_BRAIN_901_AGENT_SCHEMA

WOOD-BOOSTER AI PLATFORM
AGENT DATA SCHEMA

Version: 1.0
Status: Active
Priority: Critical

PURPOSE

This document defines the standard data structure for every AI agent inside the Wood-Booster Intelligence Platform.

The schema ensures that all agents can be registered, discovered, validated and managed consistently by the runtime.

--------------------------------------------------

MISSION

Provide one machine-readable model for every AI agent.

Each agent should be understandable by humans, the Orchestrator, the Agent Runtime and the Capability Registry.

--------------------------------------------------

REQUIRED FIELDS

agentId

Unique permanent identifier.

Example:
AI-401-CEO

--------------------------------------------------

name

Human-readable agent name.

Example:
CEO Agent

--------------------------------------------------

version

Current semantic version.

Example:
1.0.0

--------------------------------------------------

status

Allowed values:

Draft

Active

Degraded

Disabled

Retired

--------------------------------------------------

description

Short explanation of the agent's role and purpose.

--------------------------------------------------

primaryRole

The agent's main responsibility.

Example:
Strategic Leadership

--------------------------------------------------

domains

List of supported domains.

Examples:

Strategy

Finance

Workshop

Materials

Marketing

Knowledge

Customer Experience

Automation

--------------------------------------------------

capabilities

List of capabilities with level and confidence.

Each capability should include:

name

level

confidence

evidence

--------------------------------------------------

limitations

Known boundaries and prohibited actions.

--------------------------------------------------

permissions

The agent's access rules.

Include:

read

create

update

approve

delete

externalTools

--------------------------------------------------

requiredTools

Tools and integrations needed by the agent.

--------------------------------------------------

knowledgeSources

Approved information sources the agent may use.

Examples:

Constitution

Playbooks

Knowledge

Wisdom

Memory

Decision Log

Research

--------------------------------------------------

escalationTargets

Agents or humans to contact when the agent cannot continue safely.

--------------------------------------------------

runtime

Runtime configuration.

Include:

preferredModel

fallbackModels

maxContext

timeoutSeconds

maxRetries

priority

--------------------------------------------------

health

Current runtime health information.

Include:

state

lastHeartbeat

lastSuccessfulTask

currentTaskId

knownBlockers

--------------------------------------------------

performance

Measured performance values.

Include:

tasksCompleted

tasksFailed

averageResponseTime

humanEscalations

userSatisfaction

knowledgeContributions

--------------------------------------------------

audit

Audit information.

Include:

createdAt

createdBy

updatedAt

updatedBy

approvalStatus

--------------------------------------------------

--------------------------------------------------

VALIDATION RULES

- agentId must be unique.
- version must use semantic versioning.
- status must use an allowed value.
- capability levels must be between 1 and 5.
- confidence must be between 0 and 1.
- permissions must follow the Agent Permission Protocol.
- foundational agents require human approval.
- retired agents cannot receive new tasks.

--------------------------------------------------

SCHEMA EVOLUTION

When the schema changes:

1. Increment the schema version.
2. Document the change.
3. Validate existing agents.
4. Migrate incompatible records.
5. Preserve old versions for audit history.

--------------------------------------------------

SUCCESS

The Agent Schema succeeds when:

- Every agent can be registered consistently.
- The Orchestrator can select agents automatically.
- Permissions are clear.
- Runtime behavior is configurable.
- Performance and health are measurable.
- Agent records remain auditable.

--------------------------------------------------

FINAL PRINCIPLE

A reliable multi-agent platform begins with reliable agent definitions.

Every agent should have a clear identity, clear authority, clear capabilities and clear limits.
