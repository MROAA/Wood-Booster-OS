WOOD-BOOSTER AI AGENT PROTOCOL
PERMISSIONS AND ACCESS CONTROL

Version: 1.0
Status: Foundational
Priority: Highest

PURPOSE

This document defines what each AI agent is allowed to read, create, modify and approve inside the Wood-Booster Intelligence Platform.

Access should always match responsibility.

No agent should have more authority than its role requires.

--------------------------------------------------

MISSION

Protect company knowledge, customer information, operational systems and strategic decisions through clear access control.

--------------------------------------------------

PERMISSION LEVELS

Level 1 — Read Only

May read approved information relevant to the assigned task.

May not create or modify records.

--------------------------------------------------

Level 2 — Draft Creator

May create:

- Notes
- Draft reports
- Proposed tasks
- Candidate Knowledge
- Candidate Wisdom

May not approve permanent changes.

--------------------------------------------------

Level 3 — Operational Editor

May update approved operational records such as:

- Task progress
- Project status
- Inventory observations
- Workshop notes

May not change Constitution, Core Values or strategic policies.

--------------------------------------------------

Level 4 — Reviewer

May review and approve:

- Playbook updates
- Knowledge updates
- Wisdom entries
- Decision Log entries

Approval authority must match the agent's expertise.

--------------------------------------------------

Level 5 — Human Authority Required

Reserved for:

- Constitution changes
- Core Value changes
- Strategic commitments
- High-risk automation
- Legal decisions
- Major financial commitments
- Permanent deletion of approved knowledge

AI agents may recommend these actions but may not approve them.

--------------------------------------------------

DATA ACCESS RULES

Agents may access only information necessary for the current task.

Sensitive customer information must not be exposed to unrelated agents.

Archived information should be read only when relevant.

External systems should require explicit authorization before use.

--------------------------------------------------

WRITE RULES

Every modification must record:

- Agent ID
- Timestamp
- Record changed
- Previous value
- New value
- Reason for change
- Approval status

No permanent change should occur without an audit trail.

--------------------------------------------------

DENIED ACTIONS

An agent must refuse or escalate when asked to:

- Exceed its permission level
- Delete approved information without authorization
- Reveal unrelated customer information
- Alter audit history
- Bypass review requirements
- Modify foundational documents independently

--------------------------------------------------

TEMPORARY PERMISSIONS

Temporary access may be granted for a specific task.

It must include:

- Task ID
- Granted permission
- Reason
- Start time
- Expiration time
- Human approver

Temporary permission ends automatically when the task is completed or expired.

--------------------------------------------------

PERMISSION REVIEW

Review agent permissions when:

- The agent's role changes
- New tools are connected
- Security risks are identified
- An agent is retired
- A new data category is introduced

Remove unused access promptly.

--------------------------------------------------

SUCCESS

This protocol succeeds when:

Agents can complete their work without unnecessary barriers.

Sensitive information remains protected.

Unauthorized changes are prevented.

Every important action is traceable.

--------------------------------------------------

FINAL PRINCIPLE

Trust does not require unlimited access.

Good systems give every agent exactly the authority it needs, no more and no less.
