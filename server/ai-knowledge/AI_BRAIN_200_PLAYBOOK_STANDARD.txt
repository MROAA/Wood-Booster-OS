WOOD-BOOSTER AI STANDARD
PLAYBOOK SPECIFICATION

Version: 1.0
Status: Foundational
Priority: Highest

PURPOSE

This document defines the standard structure for every Playbook inside the Wood-Booster AI Brain.

A Playbook is not knowledge.

A Playbook is an approved way of performing work.

Every Playbook should be easy for both humans and AI to follow.

--------------------------------------------------

WHEN TO CREATE A PLAYBOOK

Create a Playbook when:

- A task is performed repeatedly.
- A better workflow has been verified.
- Consistency improves quality.
- New employees would benefit.
- AI agents should follow the same process.

--------------------------------------------------

REQUIRED STRUCTURE

Every Playbook must contain:

1. Title

2. Purpose

3. Scope

4. Required tools

5. Required materials

6. Preconditions

7. Step-by-step workflow

8. Quality checkpoints

9. Common mistakes

10. Safety notes

11. Completion criteria

12. Lessons learned

13. Related documents

--------------------------------------------------

STEP FORMAT

Each workflow step should include:

Step Number

Objective

Action

Expected Result

Verification

Never combine multiple major actions into one step.

--------------------------------------------------

QUALITY CHECKPOINTS

Define measurable checkpoints.

Examples:

- Dimensions verified
- Moisture measured
- Finish cured
- Customer approval received

Quality should be verified throughout the workflow, not only at the end.

--------------------------------------------------

VERSION CONTROL

Every Playbook should include:

Version

Status

Author

Last Updated

Approved By

Reason For Change

Older versions should remain archived.

--------------------------------------------------

LINKS

Every Playbook should reference:

Relevant Knowledge

Relevant Wisdom

Relevant Materials

Relevant Products

Relevant Thinking Frameworks

Relevant Projects

--------------------------------------------------

IMPROVEMENT PROCESS

After each completed project ask:

Did this Playbook work?

Should any step change?

Were new risks discovered?

Should another Playbook be created?

--------------------------------------------------

FINAL PRINCIPLE

A Playbook is the company's proven way of working today.

Tomorrow's experience should make tomorrow's Playbook even better.
