AI_BRAIN_902_PROJECT_SCHEMA

WOOD-BOOSTER AI PLATFORM
PROJECT DATA SCHEMA

Version: 1.0
Status: Active
Priority: Critical

PURPOSE

This document defines the standard machine-readable structure for every project inside the Wood-Booster Intelligence Platform.

The schema allows projects to be created, tracked, analyzed, automated and connected to customers, materials, tasks, decisions, documents and AI agents.

--------------------------------------------------

MISSION

Provide one reliable project model from the first idea to final delivery and learning review.

Every project should function both as an operational record and as a source of future knowledge.

--------------------------------------------------

--------------------------------------------------

VALIDATION RULES

- projectId must be unique.
- name is required.
- status must use an allowed value.
- customerId is required for customer projects.
- percentComplete must be between 0 and 100.
- actual completion cannot occur before actual start.
- delivered projects require final quality approval.
- completed projects require a learning review.
- cancelled and archived projects must include a reason.
- financial values must use the project's declared currency.
- all permanent changes require an audit record.

--------------------------------------------------

PROJECT STATE RULES

Idea

May contain incomplete information.

Planning

Requires goal, owner and initial scope.

Design

Requires requirements and design responsibility.

Approved

Requires human or authorized approval.

Production

Requires approved design, materials and production plan.

Quality Control

Requires production tasks to be complete.

Ready for Delivery

Requires passed final inspection.

Delivered

Requires delivery evidence.

Completed

Requires project review and captured learning.

Archived

Read-only unless explicitly restored.

--------------------------------------------------

SCHEMA EVOLUTION

When this schema changes:

1. Increment the schema version.
2. Document new and removed fields.
3. Validate existing projects.
4. Migrate incompatible records.
5. Preserve previous versions in the audit history.

--------------------------------------------------

SUCCESS

The Project Schema succeeds when:

- Every project follows one structure.
- Project status is always visible.
- Costs and schedules can be compared.
- Agents can coordinate work automatically.
- Risks and decisions remain traceable.
- Completed projects create reusable learning.
- Dashboard information remains reliable.

--------------------------------------------------

FINAL PRINCIPLE

A project is not only a collection of tasks.

It is a complete record of purpose, decisions, craftsmanship, customer value and learning.

Every project should leave Wood-Booster stronger than it found it.
